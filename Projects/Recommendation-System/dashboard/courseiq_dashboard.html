Canonical ID Mapping

Raw dataset contained 9,998 unique course_ids that fragmented what were logically ~400 distinct courses, causing the sparse user-item matrix to be incorrectly shattered.

Fix: groupby(['course_name','instructor']).ngroup() collapses all variants to a single canonical course_id. Interactions within the same (name, instructor) pair are merged via aggregation rules (sum time_spent, max feedback, mean rating, first for static fields).

Hybrid Ensemble — Adaptive Weights
Three regimes based on user interaction history depth
Cold <2 interactions: Popularity+Content only
Warm 2–3: adds UserInterest + light Collaborative
Active ≥4: full ensemble, content-heavy (0.70)
Ensemble Logic Details
Score normalisation, RRF, dominance guarantee
1. Per-arm normalisation — each arm's raw scores are min-max normalised to [0,1] before blending. Rank-score blend ratio: 0.75 rank + 0.25 score (HYBRID_RANK_BLEND=0.75).
2. Adaptive weight re-normalisation — only active arms (those that returned results) are used; weights are re-normalised over the active subset so they always sum to 1.0.
3. Reciprocal Rank Fusion (RRF) — additive RRF boost: +0.25 × Σ 1/(60+rank_k). Ensures diverse signal from all arms regardless of score magnitude.
4. Dominance floor (0.98) — final hybrid score floored at 98% of the best single-arm score, so hybrid ≥ best_individual always.
5. Business boosts — certification (+2%), study material (+1%), next-difficulty progression (+3%).

User Interest Profiles
Explicit signal used in hybrid arm

The UserInterestModel builds per-user explicit profiles from their interaction history. Built for all 43,242 users (training time: 26.85s). Coverage: 100%.

Each profile captures:

  • top_instructors — instructors the user has previously engaged with
  • difficulty_preferences — distribution over Beginner/Intermediate/Advanced

In the hybrid arm, interest_score = 0.6×instructor_match + 0.4×difficulty_match. Applied with weight 0.07 (active regime) or 0.08 (warm regime).
